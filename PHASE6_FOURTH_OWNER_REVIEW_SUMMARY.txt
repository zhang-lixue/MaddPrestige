SOURCE + TARGET STAGE PARTICIPATION MODEL

StageTransitionPermit represents the exact tuple (operation ID, source/current StageId, target/result StageId, configuration revision, UUID lease token). StageTransitionLease adds persisted diagnostic ownership/state. SQLite migration 9 rebuilds mp_stage_transition_leases with an operation foreign key, source_stage_id, target_stage_id, config_revision, unique lease_token, fixed OPERATION owner_type, participation_complete, and acquired_at. The remap store compares every removed stage against both stage positions while acquisition/remap share a BEGIN IMMEDIATE database boundary.

Legacy migration behavior is evidence based. Old rows whose owner is absent or terminal are discarded. A row for a live nonterminal owner is retained as incomplete and blocks destructive remap until that exact owner adopts it and supplies the authoritative source. Age and config revision alone never authorize deletion.

EXACT GATE POINTS AND EXECUTION ORDERING

Rank-up: validate the sealed plan, active config/provider bindings, and idempotency identity; find or insert immutable PREPARED journal ownership; acquire the exact source→target lease; recheck bindings/targets; transition PREPARED→EXECUTING; only then run costs, external projection, internal CAS/current-stage commit, and rewards. Terminal result releases; NEEDS_RECONCILIATION retains.

Prestige: validate sealed Prestige authorization/config/provider identity; find or insert PREPARED lifecycle operation; acquire exact source→reset-stage participation; revalidate projection/bindings; claim execution; only then run costs, external reset projection, atomic lifecycle/current-stage commit, and rewards. Terminal result releases; uncertain result retains.

Rank projection: establish PREPARED operation ownership; acquire the expected authoritative current stage plus projection target; recheck binding and claim execution before any external adapter call. Terminal completion releases; uncertain projection retains.

Manual/current-stage mutation: Phase 6 exposes no separate manual current-stage command. ManualPrestigeAdministrationService changes Prestige counters only and does not mutate stage. Every production direct/import/test-visible SqlitePlayerStageRepository stage writer therefore forms the manual/direct safety boundary: inside BEGIN IMMEDIATE it loads the authoritative source when present, checks source and target against pending destructive remaps, performs the CAS/write/history append, and commits. It creates no durable lease. SqlitePrestigeLifecycleRepository uses the same guard inside the outer Prestige authority.

JOURNAL-OWNED LEASE LIFECYCLE

Creation ordering: PREPARED operation journal first, lease second, effects last. SqliteStageReferenceMigrationStore refuses lease acquisition when the journal owner is absent or terminal. Thus crash before journal insertion cannot leave a lease; crash after PREPARED but before lease/effects leaves an effect-free PREPARED operation that bounded recovery can terminally fail.

Restart adoption: acquire for the same operation/source/target/config tuple returns the persisted unique token. A legacy incomplete live row may be completed only by its exact owner with its authoritative source. A mismatched tuple fails closed and no competing authority is created.

Terminal release: release requires terminal journal evidence and deletes only the exact operation/token row. Repeated and concurrent releases are idempotent. Ownership is not based on a newlyAcquired flag.

NEEDS_RECONCILIATION: the nonterminal journal state deliberately retains the lease. PendingOperationRecoveryService performs startup cleanup of leases whose owners are already terminal, preserves unresolved owners, and releases by operation ID after evidence-backed transition to COMPLETED or FAILED. Resolution and repeat cleanup release at most once.

Nested re-entry: repository methods do not own or close a durable lease. A nonterminal release attempt is a no-op, so nested repository completion cannot drop an outer executor's live authority. Only the journal's terminal state permits deletion.

Direct repository crash behavior: shared SqliteStageTransitionGuard uses the same SQLite write lock/transaction boundary as remap. A crash rolls back the direct mutation and lock; no random owner ID or durable row exists to strand a blocker.

ORPHAN PREVENTION AND CLEANUP

No production durable acquire call is reachable without an existing nonterminal operation journal. Migration and startup maintenance remove only absent-owner or terminal-owner rows using durable evidence. Malformed/incomplete participation remains visible and blocking until its exact live owner adopts it; no timeout heuristic is used. Terminal cleanup, permit release, and operation-ID recovery release are all idempotent.

MULTI-SOURCE REMAP

StageRemapPlan.withMapping merges/replaces one source and preserves every other source; withoutMapping removes one source. ConfigurationAdministrationService validates the entire candidate mapping before draft CAS: every source must be absent from the candidate, and every target must exist, be enabled, and be ordered. A successful mutation increments the draft version and invalidates preview/acknowledgement authority. An invalid second mapping makes no draft change.

Command `config remap` and opaque GUI SELECT_STAGE_REMAP use the same server-owned source-scoped selection. Command `config unmap` and GUI REMOVE_STAGE_REMAP use the same source-scoped removal. No caller can submit an arbitrary whole StageRemapPlan. B→C followed by D→E remains one sealed plan; updating B preserves D, removing B preserves D, and command/GUI reach equivalent draft state.
