CRAFTENGINE READ/REWARD/COST/SECURITY DISPOSITIONS

Requirement: NATIVE. A fully namespaced item ID is re-resolved for each current read. Online-player storage contents are scanned, and only exact public CraftEngine identity-key matches count. Unknown/removed/offline/unavailable state is unavailable, not zero. Checked addition is used.

Reward: NATIVE. A positive integral COUNT within the safety maximum is split into legal exact stacks built through the public definition on the server thread. Each stack is identity/amount verified. Capacity is simulated without writes; only empty slots or exact-identity similar stacks contribute. Inventory is rechecked before one insertion attempt. No leftovers are dropped. A leftover or exception after possible mutation is UNCERTAIN, non-idempotent, non-reversible and non-reconcilable; automatic replay is forbidden.

Cost/turn-in: UNAVAILABLE. The qualified boundary has no atomic multi-slot debit, durable operation receipt, idempotent consume, exact rollback or operation-specific reconciliation query. Read capability is not treated as mutation authority.

Cosmetic/collectible reward: an ordinary item-backed collectible uses the same native item reward. Permanent non-item cosmetic entitlement is UNAVAILABLE because no safe account/profile entitlement API was qualified.

Forgery model: material, name, lore, model and other visual similarity do not establish identity and cannot inflate count or capacity. A different CraftEngine key is rejected. Unforgeable provenance against privileged server plugins/commands that manipulate raw server state is not claimed; those actors are inside the trusted server boundary.
