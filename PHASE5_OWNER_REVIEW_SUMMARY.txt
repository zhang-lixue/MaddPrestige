IMPLEMENTED INTEGRATIONS
1. Vault: separate real CostProvider (vault_economy_cost), RewardProvider
   (vault_economy_reward), and current balance MetricProvider (vault_balance).
   One immutable service binding, server-thread scheduler, exact fractional/double
   representation gate, aggregate read-only preflight, fail-closed disappearance,
   and externally uncertain response mismatch. The Vault API has no durable
   MaddPrestige operation key/effect query, so the adapter truthfully declares
   non-idempotent, non-reversible, non-reconcilable external semantics and never
   invents compensation.

   official final XP-gain event source feeds an authenticated/batched monotonic
   exact-decimal manual total. Existing Prestige-scope baselines calculate current
   delta without resetting or editing mcMMO.
3. PlaceholderAPI: official persistent output expansion backed only by bounded
   immutable canonical snapshots; optional generic input MetricProvider performs
   controlled scheduled resolution and typed/freshness parsing. Requirement reads
   are cache-only.

   source into an authenticated manual CURRENCY_AMOUNT metric. Buy, failure,
   cancellation, inactive, non-finite and non-positive events credit nothing.
   Reliability is explicitly event-tracked only, not authoritative reconciliation.

   only. No metric/reward/manual-progress handle exists. progressionCredits() is
   hard zero and configuration enabling progression credit is rejected.

OPTIONAL / LIFECYCLE / HEALTH / GENERATION
All integrations are optional and disabled by integrations.yml. Discovery registers
providers inactive; only configuration-reachable IDs activate. Unrelated dormant
providers are not execution-critical. Dependency disable marks health unavailable
and unregisters exact bindings. Reappearance/rebind creates a new ProviderRegistry
generation. Existing canonical planning/authorization/execution pins remain the
only consequential authority, so stale plans cannot substitute the new generation.
Event acceptance is bound to the exact active registration. Dependency startup and
shutdown order therefore converge safely whether MaddPrestige or the dependency is
enabled/disabled first.

THREADING / PERFORMANCE
Vault, mcMMO and PlaceholderAPI input calls go through IntegrationTaskScheduler for
the plugin-required server-thread context. No asynchronous repository work is
blocked onto that context. Placeholder output performs only one synchronized bounded
cache lookup of an immutable snapshot. Shop/mcMMO event paths perform bounded
validation plus one in-memory manual counter increment; existing manual persistence
flushes batches and does not write SQL per event. Cache sizes are constructor-bounded.
