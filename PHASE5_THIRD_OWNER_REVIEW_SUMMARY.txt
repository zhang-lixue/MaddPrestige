AUTHORITATIVE PROVIDER ACTIVATION / HEALTH MODEL
Registry ActivationState and operational ProviderHealthState are independent:
1. dependency acquisition/probe establishes the initial operational health;
2. discover registers the provider INACTIVE and binds its exact registration gate,
   but never rewrites operational health;
3. configuration reconciliation changes only registry activation to the exact desired
   set; it never changes MutableProviderHealth;
4. config disable/re-enable therefore preserves NOT_INSTALLED, INACTIVE, DEGRADED,
   UNSUPPORTED, UNAVAILABLE, or UNHEALTHY without fabricated recovery;
5. only AVAILABLE and ACTIVE are usable by Phase 5 provider-local gates, matching the
   canonical Phase 3/4 rule;
6. an explicit successful probe may call dependencyRecovered for the exact current
   ProviderRegistration and transition that binding to AVAILABLE;
7. dependency unregister transitions the old binding to UNAVAILABLE and removes its
   exact token/generation; stale recovery and stale gates reject;
8. successful reacquisition supplies a newly healthy provider/gate and registration.

Configuration remove/add and unchanged desired reconciliation retain the same registry
token and generation. Exact same-binding recovery also retains generation. Only actual
unregister/rebind advances generation. The regression matrix proves AVAILABLE/ACTIVE
normal activation, every unusable state remaining unchanged through desired and off/on
transitions, explicit recovery, unchanged generation, unregister/rebind generation +1,
stale rejection, dormant outage isolation, and compiled config -> plan -> lifecycle ->
canonical RequirementMetricCollector blocking with zero provider reads while unhealthy.

CANONICAL USABLE-HEALTH PREDICATE
MutableProviderHealth.isUsable is the single Phase 5 provider-local allowlist:
- AVAILABLE: usable
- ACTIVE: usable
- NOT_INSTALLED: blocked
- INACTIVE: blocked
- DEGRADED: blocked
- UNSUPPORTED: blocked
- UNAVAILABLE: blocked
- UNHEALTHY: blocked

Vault, mcMMO and Placeholder input use this predicate. Canonical core consumption still
independently requires exact generation plus ACTIVE registry activation and AVAILABLE or
ACTIVE health. No provider-local blacklist remains in the new Phase 5 providers.

PLACEHOLDER REFRESH OUTAGE GATE
PlaceholderInputMetricProvider requires a health-bound gate for provider ID
placeholder_input. ProviderRegistrationGate binds exactly once to the registry token and
generation returned by registration. The scheduled refresh task itself calls allowsUse
before each PlaceholderAPI resolver call and again before caching the returned value; the
check is not only performed before scheduling.
Tests prove:
- healthy refresh: exactly one resolver call;
- unhealthy before scheduling: zero resolver calls;
- healthy when scheduled, unhealthy before deferred execution: zero resolver calls;
- unavailable: zero resolver calls;
- unregistered/rebound old task: zero resolver calls;
- outage during a multi-input resolver call: returned value discarded and remaining
  resolver calls suppressed;
- new valid generation: refresh resumes;
- failed/gated refresh does not mutate requirement state or replace cache;
- prior cache remains deterministic and becomes readable after legitimate recovery if
  still fresh.

MCMO EXACT-REGISTRATION EVENT GATE
McMmoAdjustedXpListener no longer accepts BooleanSupplier. Its constructor requires a
ProviderRegistrationGate and rejects a gate for any provider other than mcmmo. For every
event, the gate requires the exact bound token/generation to remain current, registry
activation ACTIVE, and operational health AVAILABLE/ACTIVE before the authenticated
ManualMetricHandle can increment.

Generation-1 healthy events credit exactly once. UNHEALTHY, UNAVAILABLE, DEGRADED,
config deactivation and dependency unregister reject with zero additional progression.
After generation-2 rebind, the old listener still rejects and the new current listener
accepts. Explicit same-binding recovery resumes only after its successful probe. Existing
cancelled-event protection remains and the separate manual adjusted-XP descriptor remains
monotonic.
